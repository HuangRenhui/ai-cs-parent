```http
Content-Type: application/json

```

### 统一响应格式

```json

  "msg": "success",
```

**失败响应**：`code` 为错误码，`message` 为错误描述

## 2. 认证与授权（Base Service）

**Controller**: `AuthController` | **路径前缀**: `/auth`

### 2.1 运营后台登录

> 无需认证（`@NoAuth`）。**准入角色受限**，见下方「准入约束」。

```http
POST /auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "password123",
  "loginType": "admin"
}
```

**响应**：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "username": "admin",
    "realName": "超级管理员",
    "roles": ["SUPER_ADMIN"],
    "loginType": "admin"
  }
}
```

**准入约束（安全要求，不能只靠前端隐藏入口）**

运营后台承载全量客户数据与平台配置，本入口**只放管理员与超级管理员**：

| 情况 | 结果 |
|------|------|
| 账密正确 + 角色为 `SUPER_ADMIN` / `ADMIN`（或角色名含「管理」） | 签发 JWT，`loginType=admin` |
| 账密正确 + 其它角色（坐席、普通用户等） | `401` —— `该账号不是管理员，请从「普通用户登录」入口进入` |
| 账号为种子 `admin` 且尚未绑角色 | 放行，避免初始化后被锁死 |
| 请求带 `loginType=platform` | `400` —— `平台账号请从「普通用户登录」入口进入` |

实现位置：`UserService.assertAdminEntrance`，在**密码校验通过之后**调用，因此不会向未通过账密校验的请求泄露角色信息。

> 前端已把两个入口拆成独立页面（`/login` 与 `/login/admin`），并在表单上方标注准入规则；
> 但**唯一防线在服务端**——前端隐藏入口挡不住直接构造请求。

### 2.2 获取当前用户信息

```http
GET /auth/userinfo
Authorization: Bearer <token>
```

**响应**：
```json
{
  "code": 200,
  "data": {

    "username": "admin",

    "avatar": "/avatars/default.png",

    "permissions": ["system:user:list", "system:role:list", ...]
  }
}
```

### 2.3 获取当前用户菜单

```http
GET /auth/menus
Authorization: Bearer <token>
```

**响应**：返回用户拥有的菜单树

### 2.4 退出登录

```http
POST /auth/logout
Authorization: Bearer <token>
```

---

### 2.5 普通用户（平台）登录

> 无需认证（`@NoAuth`）。C 端入口，与 §2.1 的账号体系**不通**。

```http
POST /auth/login/platform
Content-Type: application/json

{
  "tenantCode": "default",
  "username": "agent001",
  "password": "******",
  "ssoTicket": ""
}
```

带 `ssoTicket` 时视为对接平台已完成单点校验，不再比对本地密码。

**响应**：`roles=["AGENT"]`，`loginType=platform`，并回显 `tenantCode`。

| 情况 | 结果 |
|------|------|
| 坐席账号 + 正确密码 | 签发 JWT，`loginType=platform` |
| `admin` 走本入口 | `401` —— `管理员请从「运营后台登录」入口进入` |
| 缺 `tenantCode` | `401` —— `请填写对接平台的租户编码` |

实现位置：`AgentService.loginFromPlatform`。两个入口互相拒绝对方账号，避免身份混在同一表单。

### 8.4 AI 工具注册

**Controller**: `AiToolController`（**后端未完成**，内存桩） | **路径前缀**: `/system/ai-tool`

AI 工具箱原先的工具清单硬编码在前端 `catalog`，无法新增。这组接口用于**动态注册自定义工具**，并支持把执行绑定到外部开放接口。页面 `/ai/tools`。

```http
GET /system/ai-tool/list?tenantCode=

DELETE /system/ai-tool/delete/{id}
```

工具定义字段：`code`（唯一，会成为路由 `/ai/tools/{code}`）、`name`、`category`、`summary`、`hint`、`icon`、`color`、`enabled`，以及执行方式二选一：

- `execType=builtin` + `panelCode`：复用 5 个内置面板（`entry`/`import`/`batch-delete`/`faq-draft`/`ticket-fill`）
- `execType=http` + `httpMethod` + `apiUrl`：工作台走通用 HTTP 面板发起请求

## 10. AI Agent 对话

**Controller**: `AiChatController` | **路径前缀**: `/ai`

### 10.1 文本对话（核心接口）

```http
POST /ai/chat/send
Content-Type: application/json

{
  "sessionId": "session_123",
  "customerId": 1,
  "msg": "如何重置密码？",
  "attachments": [
    {
      "fileId": "a1b2c3d4e5f6",
      "url": "/files/chat/a1b2c3d4e5f6.png",
      "fileName": "屏幕截图.png",
      "category": "image",
      "contentType": "image/png",
      "fileSize": 204800
    }
  ],
  "context": { ... }
}
```

**响应**：`Result<String>` - AI 生成的回复文本

**关于附件与 `msg`**：

- 支持 **「文字 + 图片/附件」** 与 **「纯附件不发文字」** 两种发法。因此 `msg` **不再强制非空**（`ChatDTO` 已移除 `@NotBlank`），改由业务层判断「`msg` 与 `attachments` 至少有一项」。纯附件消息时 `msg` 按空串落库，避免拼接上下文出现 `"null"`
- 附件先调 `POST /file/chat-attachment` 上传拿到元信息，再随本接口的 `attachments` 一起提交
- 附件随用户消息**落库到 `cs_chat_msg.attachments`**（JSON 列），前端拉取历史消息时按该字段回显；落库失败仅记录告警，不影响本次回复返回
- 流式接口 `POST /ai/chat/stream` 同样支持 `attachments`；纯附件时以「（用户上传了 N 个附件）」作为占位内容送入模型
- **当前 AI 尚不能理解附件内容**（`parseStatus=0`）：附件只做上传、展示、落库；多模态理解待模型层打通后接入

```http
PUT    /api/prompt/version/{id}/rollback

```

| 接口 | 说明 |
|------|------|
| `list` | 版本列表，**必须带 `config` 快照** —— 前端「版本对比」直接在这份数据上做字段 diff，不再单独拉详情 |
| `save` | 存为新版本，`changeNote` 必填；新版本一律落为 `draft` |
| `publish` | `grayScale=100` 全量发布，`0~99` 灰度；全量时同 `target` 旧的 `published` 自动降级为 `draft` |
| `rollback` | 把该版本快照写回生效配置；同 `target` 其它在线版本降级 |
| `delete` | `published` / `gray` 状态拒绝删除，否则线上无处可回退 |

> **当前为内存桩**：数据存 Controller 本地 List，**服务重启即丢**，仅用于跑通前后端契约。
> 待建表 `cs_prompt_version`，关键约束（同 target 唯一 published、生效中禁删、灰度按
> `tenantCode + sessionId` 一致性哈希、发布与回滚写操作审计）见
> [提示词版本与评测-接口约定](提示词版本与评测-接口约定.md)。

### 15.15 提示词效果评测（内存桩）

**Controller**: `PromptEvalController` | **路径前缀**: `/api/prompt/eval`

```http
GET    /api/prompt/eval/set/list
POST   /api/prompt/eval/set/save
PUT    /api/prompt/eval/set/update
DELETE /api/prompt/eval/set/delete/{id}
GET    /api/prompt/eval/case/list?setId=
POST   /api/prompt/eval/case/save
DELETE /api/prompt/eval/case/delete/{id}
POST   /api/prompt/eval/run
GET    /api/prompt/eval/run/list
GET    /api/prompt/eval/run/{id}
```

- `set/list` 带 `caseCount`，前端直接展示，不用再逐集查询
- `case/save` 的 `mustRefuse=1` 表示这条期望模型拒答，**给了具体方案即算失败**
- `run` 同步返回完整报告；`run/list` **不含逐条 `details`**，避免列表随报告增多变重
- 判定按三级规则：`mustRefuse` 拒答校验 → `expectHit` 召回校验 → `expected` 语义相似度

> **当前为内存桩**：`run` 返回演示报告，**未真正调用问答链路**。待建表
> `cs_prompt_eval_set` / `case` / `run` / `run_detail`。用例与期望答案需在报告中**存快照**，
> 事后改用例不影响历史报告的结论。

| 接口 | 用途 |
|------|------|
| `list` | **后台维护用**，返回全部配置（含停用项），按排序号升序 |
| `get` | **对外初始化用**，取启用项中排序号最小的一套；一套都没有则退回第一套 |
| `save` / `update` | 新增 / 编辑，`configName` 必填 |
| `{id}/enabled` | 启用 / 停用 |
| `delete/{id}` | 删除；删除生效中的配置前需确认客户端能回退到其它启用项 |

> **当前为内存桩**：数据存 Controller 本地 List，**服务重启即丢**。待建表 `cs_widget_config`
> （`tenant_code` 隔离）。注意 `GET /get` 是对外接口，响应里**不要带 `enabled` / `sortNum`
> 等后台管理字段**。
