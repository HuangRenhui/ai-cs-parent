  - **增强功能**:
  - ✓ 对象存储集成（支持本地/MinIO/OSS/COS多种存储策略）
  - ✓ CDN加速（可配置CDN域名，自动生成CDN访问URL）
  - ✓ 批量上传和处理（支持并发处理、进度追踪）
  - ✓ 图片OCR文字识别（提取图片中文字内容用于知识库检索）

  - ✓ 批量上传和处理（支持并发处理、进度追踪）
  - ✓ 音频语音识别ASR（Whisper集成框架，将语音转为文字）
  - ✓ 音频AI审核（内容安全检测框架）
  - ✓ 音频智能标签（基于元数据自动标签，支持预定义标签库）

  - ✓ 音频访问统计（记录播放量、下载量，热门音频排行）

#### 11.3 图片/音频向量化与入库

  - ✓ 音频元数据/转录文本向量化（基于文件名、时长、格式、元数据等生成描述）
  - ✓ 向量化存储到Chroma向量库（图片集合、音频集合分别存储）
  - ✓ 自然语言语义搜索（支持按描述搜索相似图片/音频）
  - ✓ 批量向量化支持
  - ✓ 上传后自动向量化（可配置）
  - **增强功能**:
  - ✓ 多模态混合检索（图文音频融合搜索，结果统一排序）
  - ✓ 跨模态语义搜索（用图片描述搜音频，或反之）
  - ✓ 图文混合问答（结合图片和文本知识库的综合检索）

#### 11.4 文件查看、下载与解压
  - ✓ 文件在线预览（图片、PDF、音频、视频，浏览器内联展示）
  - ✓ 按文件ID预览（支持images/audios/documents/thumbnails等存储类型）
  - ✓ 文件下载（Content-Disposition: attachment，支持HTTP Range断点续传）
  - ✓ 压缩包解压（支持ZIP、7Z、TAR、TAR.GZ、BZ2、TGZ格式）
  - ✓ 批量文件打包下载（多文件打包为ZIP）
  - ✓ 压缩包内容查看（不解压即可浏览压缩文件内文件列表）
  - ✓ 解压后文件预览与列表查看
  - ✓ Zip炸弹防护（限制解压大小和文件数量）

  - ✓ 文件信息查看（大小、类型、是否可预览等元数据）
  - ✓ 目录文件列表（支持递归列出子目录）
  - ✓ 静态资源URL映射（支持直接URL访问文件）
  - ✓ CORS跨域访问配置

## 技术改造计划

### 1. WebSocket 替换为 Netty 改造方案

#### 1.1 现状分析
- **当前实现**: Spring WebSocket (JSR-356)
- **优点**: 
  - 与 Spring Boot 无缝集成
  - 开发简单，维护成本低
  - 满足当前业务需求
- **缺点**:
  - 同步阻塞 IO，并发能力有限
  - 内存占用较高
  - 扩展性受限于 Servlet 容器

#### 1.2 Netty 改造可行性评估

✅ **改造优势**:
- **高性能**: 异步非阻塞 IO，单机可支持数十万并发连接
- **低延迟**: 零拷贝技术，减少数据复制开销
- **资源节省**: 更少的线程消耗，降低内存占用
- **协议灵活**: 支持自定义协议，易于扩展
- **稳定性**: 经过大量生产环境验证

⚠️ **改造挑战**:
- **开发成本**: 需要重写整个 WebSocket 模块（预计 2-3 周）
- **学习曲线**: 团队需要掌握 Netty 框架
- **Spring 集成**: 需要手动处理依赖注入、事务等
- **测试工作量**: 需要全面的压力测试和稳定性测试
- **运维复杂度**: 监控、日志、异常处理需要重新设计

📊 **决策建议**:
| 场景 | 建议 | 理由 |
|------|------|------|
| 当前用户量 < 1万并发 | ❌ 不建议改造 | Spring WebSocket 已足够，ROI 低 |
| 用户量 1-10万并发 | ⚠️ 谨慎评估 | 可先优化现有代码，观察性能瓶颈 |
| 用户量 > 10万并发 | ✅ 推荐改造 | Netty 优势明显，值得投入 |
| 有长期高并发规划 | ✅ 提前布局 | 作为技术储备，分阶段实施 |

#### 1.4 技术选型对比

| 特性 | Spring WebSocket | Netty |
|------|-----------------|-------|
| 并发能力 | 中等（千级） | 高（十万级） |
| 开发难度 | 低 | 中高 |
| 维护成本 | 低 | 中 |
| 性能 | 良好 | 优秀 |
| 生态集成 | 优秀 | 需手动集成 |
| 适用场景 | 中小规模应用 | 大规模高并发应用 |

#### 1.5 风险评估与应对

| 风险 | 影响程度 | 应对措施 |
|------|---------|---------|
| 开发延期 | 中 | 预留缓冲时间，分里程碑验收 |
| 兼容性问题 | 高 | 充分的测试覆盖，灰度发布 |

| 团队技能不足 | 中 | 提前培训，引入外部专家 |
