## 1. 环境

- JDK 17、Maven 3.8+、Node 18+（前端 Vite 5）
- MySQL 8、Redis、Chroma/Milvus（见 [快速开始](快速开始.md)）

## 2. 拉取与构建

```bash
git clone https://gitee.com/huangrenhui/ai-cs-parent.git
cd ai-cs-parent
mvn -DskipTests package
cd ai-cs-frontend && npm install && npm run dev
```

## 3. 工程结构

见 [模块说明](模块说明.md) 与根 `pom.xml`。

## 4. Git 约定

- 分支：`main` 为主干；按 `feat(module): 中文说明` 提交
- 远程：只推 `origin`（Gitee），随后再同步 GitHub
- 不提交本地 IDE / 编辑器配置目录，提交时排除，不写入 `.gitignore`

## 5. 前端与全渠道适配

前端（`ai-cs-frontend`）为 Vue 3 + Element Plus，需同时适配 **PC / 平板 / 手机**。断点统一（`src/assets/responsive.css`）：

| 断点 | 说明 |
|------|------|
| `>1024px` | 桌面端：左侧固定菜单、多列布局 |
| `641–1024px` | 平板：窄侧栏，布局列数收紧 |
| `≤640px` | 手机：顶部抽屉菜单、单列堆叠、表格横向滚动、弹窗近全屏 |

通用规则：

- 新页面优先复用 `.page-card` / `.page-toolbar`，不要写死 `width`
- 表格依赖全局横向滚动，不要强制不换行
- 弹窗不再写死大宽度；移动端由 `responsive.css` 接管
- 新交互控件点击区 ≥ 36px；触屏时 `responsive.css` 自动放大
- 提交前至少用浏览器 DevTools 分别以手机 / 平板 / 桌面宽度走一遍

## 6. 调试

- 网关日志带 `X-Request-Id`；前端 `request.js` 已按业务码 reject
- 模型管理问题先看 [AI模型统一管理](AI模型统一管理.md)

## 前端开发

### 1. 安装依赖

```bash
cd ai-cs-frontend
npm install
```

### 2. 配置 API 地址

`request.js` 使用 `baseURL: '/api'`，由 Vite 代理到网关 8080 并去掉 `/api` 前缀。不要改成直连 `http://localhost:8080/api`。

### 2.1 演示假数据 vs 真实后端

本地默认走前端内存假数据（`ai-cs-frontend/.env.development` 里 `VITE_USE_REAL_API=false`），不启动 Java 服务也能点页面。右上角会出现「演示数据」标记。

**联通真实后端时**（网关 8080 等服务已启动）：

1. 把 `ai-cs-frontend/.env.development` 里的 `VITE_USE_REAL_API` 改成 `true`：

```
VITE_USE_REAL_API=true
```

2. **必须重启**前端开发服务，环境变量才会生效：

```bash
# 在运行 npm run dev 的终端里 Ctrl+C 停掉，再执行：
cd ai-cs-frontend
npm run dev
```

只改文件、不重启 `npm run dev`，页面仍会走假数据。改回 `false` 同样要重启。

### 3. 启动开发服务器

```bash
npm run dev
```

前端应用将在 http://localhost:5173 启动（默认端口）。

### 4. 构建生产版本

```bash
npm run build
```

构建产物将输出到 `dist` 目录。

## 开发流程

### 分支模型：main 为主干

**只用 `main` 一条长期分支**，功能与修复都开短命分支、验完合回 `main`。**不用 `develop`，不引入 Git Flow。**

| 分支 | 用途 |
|------|------|
| `main` | 唯一主干，始终可构建、可部署 |
| `feat/<模块>-<简述>` | 新功能，从 `main` 分出，合回 `main` |
| `fix/<模块>-<简述>` | 缺陷修复，从 `main` 分出，合回 `main` |

```bash
# 开新功能
git checkout main && git pull origin main
git checkout -b feat/base-customer-management

# 提交与推送
git add .
git commit -m "feat(base): 添加客户管理功能"
git push origin feat/base-customer-management
```

**远程**：以 `origin`（Gitee）为主要远程，随后再同步 GitHub —— 与上面 §4「Git 约定」一致。

**合并要求**：合并前本地跑 `mvn test`。当前**没有 CI**（见本文「CI/CD 与灰度」），所以合并前的本地自测是唯一门禁，大改（如 Netty）更要在 `main` 上先验证。

### 代码提交规范

格式、Type 类型与示例见 [编码规范](编码规范.md) 的「Git 提交规范」一节，本文不重复。

补充一条：`<scope>` 用模块名（`agent` / `knowledge` / `base` / `workorder` / `open` / `ops` / `frontend` / `docs`），与仓库目录名保持一致。

### 开发新功能步骤

1. **开分支**
   ```bash
   git checkout main && git pull origin main
   git checkout -b feat/customer-management
   ```

2. **编写代码**
   - 遵循 [编码规范](编码规范.md)
   - 编写单元测试
   - 更新相关文档

3. **本地测试**
   ```bash
   mvn test
   ```

4. **提交并推送**
   ```bash
   git add .
   git commit -m "feat(base): 添加客户管理功能"
   git push origin feat/customer-management
   ```

5. **发起 Pull Request 合回 `main`**
   - 在 Gitee / GitHub 上发起 PR，指定审查者
   - 审查通过后合入 `main`；**无流水线兜底，合并前必须本地跑过测试**
   - 合并后删掉短命分支：`git branch -d feat/customer-management`

### 调试技巧

#### 后端调试

1. **启用日志**

在 `application.yml` 中调整日志级别：

```yaml
logging:
  level:
    com.ai.cs: DEBUG
    org.springframework.web: DEBUG
```

2. **远程调试**

```bash
java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005 -jar app.jar
```

然后在 IDE 中配置 Remote Debug。

#### 前端调试

1. **浏览器开发者工具**
   - 使用 Vue Devtools 插件
   - 查看 Network 面板的 API 请求

2. **控制台日志**
   ```javascript
   console.log('Debug info:', data);
   ```

## CI/CD 与灰度

- **现状**: 无 GitLab CI / GitHub Actions / Jenkins；Pull Request 不会自动跑测试。
- **建议**: 最小流水线 = `mvn test` + 构建镜像；覆盖率 80% 是目标，当前未达（[测试指南](测试指南.md)）。
- **灰度**: 大改（Netty 等）见 [功能清单](功能清单.md) 第 20 节；WebSocket 未做会话同步前不要多副本灰度。
- **Nacos / K8s**: 可选，不挡单机可售闭环。

## 🔧 常见问题

### 1. Maven 依赖下载失败

**问题**: 依赖下载缓慢或失败

**解决方案**:

配置阿里云 Maven 镜像，编辑 `~/.m2/settings.xml`：

```xml
<mirrors>
  <mirror>
    <id>aliyun</id>
    <mirrorOf>central</mirrorOf>
    <name>Aliyun Maven Mirror</name>
    <url>https://maven.aliyun.com/repository/public</url>
  </mirror>
</mirrors>
```

### 2. 端口被占用

**问题**: 服务启动时提示端口已被占用

**解决方案**:

```bash
# Windows: 查找占用端口的进程
netstat -ano | findstr :8080
taskkill /PID <PID> /F

# Linux/Mac: 
lsof -i :8080
kill -9 <PID>
```

或者修改配置文件中的端口号。

### 3. 数据库连接失败

**问题**: 服务启动时无法连接数据库

**检查清单**:
- MySQL 服务是否启动
- 数据库是否已创建
- 用户名密码是否正确
- 防火墙是否阻止连接

### 4. Redis 连接失败

**问题**: 无法连接 Redis

**解决方案**:

```bash
# 检查 Redis 是否运行
redis-cli ping

# 应该返回 PONG
```

### 5. 前端跨域问题

**问题**: 前端调用 API 时出现 CORS 错误

**解决方案**:

网关已配置 CORS，确保前端请求通过网关（端口 8080），而不是直接访问后端服务。

### 6. Milvus 连接失败

**问题**: 知识库服务无法连接 Milvus

**解决方案**:

确保 Milvus 已启动：

```bash
# 使用 Docker 启动 Milvus
docker-compose up -d
```
