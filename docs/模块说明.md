## 🔗 模块依赖关系

```
ai-cs-parent/
├── pom.xml
├── docs/                      # 手册，见 文档说明.md
│   └── database/init.sql
│
├── ai-cs-common/              # JAR：Result、异常、DTO、工具
├── ai-cs-api/                 # JAR：Feign 接口 + Fallback
│
├── ai-cs-gateway/             # :8080  统一入口
├── ai-cs-websocket/           # :8081
├── ai-cs-agent/               # :8082
├── ai-cs-knowledge/           # :8083
├── ai-cs-base-service/        # :8084
├── ai-cs-workorder/           # :8085
├── ai-cs-open/                # :8086
├── ai-cs-ops/                 # :8087
├── ai-cs-job/                 # :8088
└── ai-cs-frontend/            # Vite :5173
```

运行时依赖（简图）：

```
ai-cs-common
    ↑
    ├─ ai-cs-api
    │     ↑
    │     ├─ ai-cs-agent        → KnowledgeFeign / OpenToolFeign / WorkOrderFeign
    │     ├─ ai-cs-workorder    → BaseServiceFeign
    │     └─ ai-cs-base-service → KnowledgeFeign / Session 等
    │
    ├─ ai-cs-gateway
    ├─ ai-cs-knowledge / ai-cs-open / ai-cs-ops / ai-cs-job
    ├─ ai-cs-websocket
    └── ai-cs-frontend → 开发时代理到网关 8080
```

## 1. ai-cs-common（公共模块）

**类型**: JAR（无独立端口）  
**依赖**: 无  
**被依赖**: 所有业务模块  

放统一 `Result`、全局异常、`BaseEntity`、DTO/枚举、安全注解、工具类，以及模型路由（`ModelRouter` / OpenAI 兼容客户端）。不要在此写业务 Controller。

**主要包结构**：

| 包 | 内容 |
|----|------|
| `result/` | 统一返回 `Result`、分页 `PageResult` |
| `exception/` | `BusinessException` + `GlobalExceptionHandler` |
| `dto/` | `ChatDTO`、`LoginDTO`、`WorkOrderDTO`、`NotificationDTO` 等 16+ DTO |
| `entity/` | 审计字段基类 `BaseEntity` |
| `enums/` | `IntentEnum`、`MsgTypeEnum`、`AgentStatusEnum`、`SessionStatusEnum`、`WorkOrderStatusEnum` |
| `constant/` | `PromptConst`（提示词模板）、`RedisKeyConst` |
| `llm/` | `ModelRouter`（路由）、`DashscopeModelClient`、`OpenAiCompatClient`（OpenAI 兼容）、熔断、用量记录 |
| `security/` | `JwtContext`、`JwtSettings`、`@NoAuth`、`@RequirePermission` |
| `util/` | `JwtUtil`、`SecretCipherUtil`（AES-GCM 密钥加密）、`ValidateUtil` |
| `service/` | `NotificationService`（通知框架）、`DataExportService`（CSV 导出） |
| `web/` | `RequestIdFilter`（请求 ID 透传） |
| `config/` | `MyMetaObjectHandler`（MyBatis-Plus 自动填充） |

能力总览见 [模块能力 §1](模块能力.md#1-微服务架构基础)。

## 2. ai-cs-api（接口模块）

**类型**: JAR  
**依赖**: ai-cs-common、OpenFeign  
**被依赖**: 需要跨服务调用的模块  

只定义 Feign 接口与 Fallback。路径与对应 Controller 对齐，避免循环依赖。

Feign 清单见 [接口说明](接口说明.md) 第 26 节；能力见 [模块能力 §25](模块能力.md#25-质量保障通知与导出)。

## 3. ai-cs-gateway（网关）

**类型**: Spring Boot 应用  
**端口**: **8080**  
**依赖**: Spring Cloud Gateway、jjwt  

统一 HTTP / WS 入口：路由转发、JWT 过滤器、请求日志、`X-Request-Id`、下游用户头。限流 Bean 已有、路由未挂载。无 Nacos 时直连 `localhost` 端口。

**路由**: `/ws/**` `/ai/**` `/knowledge/**` `/api/rag/**` `/api/image/**` `/api/audio/**` `/api/file/**` `/auth/**` `/customer/**` `/session/**` `/agent/**` `/file/**` `/files/**` `/open/**` `/ops/**` `/workorder/**` 等，以仓库 `application.yml` 为准。

能力与缺口见 [模块能力 §22](模块能力.md#22-gateway-增强)。

## 5. ai-cs-agent（AI 代理）

**类型**: Spring Boot 应用  
**端口**: **8082**  
**依赖**: ai-cs-common、ai-cs-api、LangChain4j  

调 LLM、意图路由、经 Feign 调知识库 / 开放工具 / 工单。对话走 `ModelRouter`（未登记时回退 `DashscopeModelClient` / `ai.llm`）；提示词走 `PromptConst`。`LlmUtil` 做意图解析；咨询失败返回繁忙话术，不回退闲聊。

**Controller**: `AiChatController`（`/ai`）

**外部**: 通义等 LLM；配置为本模块 `application.yml` 的 `ai.llm.*`。知识库同一套 `ai.llm` / `ai.embedding`。

能力见 [模块能力 §2](模块能力.md#2-ai-智能对话)、[§18](模块能力.md#18-ai-agent-增强)。

## 6. ai-cs-knowledge（知识库）

**类型**: Spring Boot 应用  
**端口**: **8083**  
**依赖**: ai-cs-common、LangChain4j、Chroma/Milvus、Thumbnailator、JAVE2/FFmpeg  

FAQ、RAG、文档版本、知识库侧图片/音频/文件、多模态、图谱、Prompt 调试。会话气泡富媒体不是本模块接口。

**Controller**:
- `FaqController`（`/knowledge`）
- `RagController`（`/api/rag`）
- `DocumentVersionController`（`/api/document/version`）
- `ImageController`（`/api/image`）
- `ImageEnhanceController`（`/api/image/enhance`）
- `AudioController`（`/api/audio`）
- `AudioEnhanceController`（`/api/audio/enhance`）
- `FileController`（`/api/file`）
- `KnowledgeGraphController`（`/api/knowledge-graph`）
- `MultimodalKnowledgeController`（`/api/multimodal-knowledge`）
- `MultimodalSearchController`（`/api/multimodal`）
- `KnowledgeEnhancedController`（`/api/knowledge-enhanced`）
- `PromptDebugController`（`/api/prompt`）

**表**: `cs_knowledge_faq`、`cs_knowledge_miss`、`cs_document_version`、`cs_knowledge_graph_node`、`cs_knowledge_graph_relation`、`cs_multimodal_knowledge`（后三张为半成品；图谱 yml 默认关闭）

**外部**: Ollama 或云端 embedding/rerank、Chroma 或 Milvus、Redis（RAG 会话）、可选 Neo4j/Nebula

能力见 [模块能力 §3](模块能力.md#3-知识库-rag-系统)、[§6](模块能力.md#6-rag-检索召回优化)、[§7](模块能力.md#7-prompt-调试增强六大策略)、[§12](模块能力.md#12-rag-高级功能)、[§13](模块能力.md#13-多媒体文件处理)、[§14](模块能力.md#14-知识库增强)。

## 8. ai-cs-workorder（工单）

**类型**: Spring Boot 应用  
**端口**: **8085**  
**依赖**: ai-cs-common、ai-cs-api、MyBatis-Plus、Flowable 7.0.0  

工单 CRUD。Flowable 依赖已引入，`flowable.enabled` 默认 **false**，`WorkOrderFlowController` 默认不注册。不要在本模块建订单/物流表。

**Controller**:
- `WorkOrderController`（`/workorder`；列表为 `GET /workorder/page`）
- `WorkOrderFlowController`（`/workorder/flow`，需打开 Flowable）

**表**: `cs_work_order`；BPMN 在模块资源目录

能力见 [模块能力 §4](模块能力.md#4-工单系统基础)、[§19](模块能力.md#19-工单系统增强)。

## 12. ai-cs-frontend（前端）

**类型**: Vue 3 应用  
**端口**: **5173**（Vite）  
**技术栈**: Vue 3 + Vite + Element Plus + ECharts + Axios  

运营后台（登录、聊天演示、客户/知识/工单、开放配置、AI 模型管理、运维页）与 C 端 `/widget`。开发时 `/api` 代理到网关 8080。


## 💡 开发约定

1. 业务写在对应服务的 Entity / Mapper / Service / Controller；跨服务只经 `ai-cs-api` 的 Feign。
2. 通用 DTO、枚举、异常放 `ai-cs-common`，改完 `mvn clean install` 再编其它模块。
3. 表结构改 `docs/database/init.sql` 并同步 [数据库设计](数据库设计.md)。
4. 不要循环依赖；`ai-cs-common` 保持无业务。
5. 密钥用环境变量，不要写进 Git。Nacos 默认关闭，见 [配置说明](配置说明.md)。
6. 新能力的状态写进 [模块能力](模块能力.md)，不要只改本文的一句话摘要。

启动顺序与依赖中间件见 [快速开始](快速开始.md)。
