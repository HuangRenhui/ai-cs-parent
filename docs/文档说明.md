# 文档说明

智语智能客服（`ai-cs-parent`）**v1.0** 正式手册。现行文件为中文文件名，平铺在 `docs/` 下；建表脚本在 `docs/database/init.sql`。

**数据库初始化仅需执行 `docs/database/init.sql`**，包含全部 38 张表与演示种子数据。Docker 挂载需要该英文路径。列定义导读见 [数据库设计](数据库设计.md)。配置一律直接改各服务已有的 `application.yml`。

## 维护

- 改端口：改各模块 `application.yml`，再改 [系统架构](系统架构.md) 与 [快速开始](快速开始.md)。
- 改产品分期与开发顺序：改 [功能清单](功能清单.md)；代码对照写在 [项目现状](项目现状.md)。
- 改各模块能力条目：改 [模块能力](模块能力.md)。
- 工程项（Nacos、MQ、CI、覆盖率、K8s、API 签名等）：写 [功能清单](功能清单.md) §16 / §18 / §21 与 [项目现状](项目现状.md)。
- 改表结构：改 `database/init.sql` 与 [数据库设计](数据库设计.md)。**已上线的库需同步写 `ALTER TABLE` 迁移语句**（如 `cs_chat_msg.attachments`）。
- 文档修订不写进 [功能清单](功能清单.md)，变更以 git 提交信息为准。
- 提示词改 [提示词说明](提示词说明.md) 与源码 `PromptConst`；模型配置改 [配置说明](配置说明.md) 与 [AI模型统一管理](AI模型统一管理.md)。
- 占位登记：写 [后端未完成清单](后端未完成清单.md) §2.1（内部方法桩）或 §2.1.1（按模块逐条），并在 §2.1.2 记录校验结果，同时同步 [接口说明](接口说明.md) 同节标注。
- 「可以页面化但还没做」的候选项（意图目录、检索参数、定时任务、告警规则等）：登记到 [提示词与向量页面配置](提示词与向量页面配置.md) §7，开工时才动代码。
- 体例：每篇含「文档信息」；篇幅较长时含「目录」；文末含「相关文档」。交叉引用使用同目录相对路径。

### 单一事实来源（SSOT）与维护纪律

同一事实**只允许一处权威**，其余文档只做引用或摘要，禁止各自维护一份数字：

| 事实 | 唯一权威 | 其它文档的处理方式 |
|------|---------|------------------|
| 占位方法数与逐条行为 | [后端未完成清单](后端未完成清单.md) §2 / §2.1 / §2.1.1 | 只回链，不复制数字（`文档说明`、`模块能力` 等一律引用） |
| 接口路径、参数、响应 | [接口说明](接口说明.md)（与源码 Controller 冲突时，先核实后改本文；Knife4j 仅辅助） | 其它文档只给用途，不给完整字段表 |
| 端口与路径前缀 | [配置说明](配置说明.md)（以各模块 `application.yml` 实测为准） | [系统架构](系统架构.md)、[模块说明](模块说明.md) 只回链 |
| 表结构 | `database/init.sql` | [数据库设计](数据库设计.md) 只做导读与索引说明 |
| 能力「已实现 / 占位」 | [后端未完成清单](后端未完成清单.md)（功能维度） + [生产化差距清单](生产化差距清单.md)（非功能维度） | [模块能力](模块能力.md)、[项目现状](项目现状.md) 只写状态并回链 |
| 前端页面与路由 | [前端信息架构](前端信息架构.md) | [模块能力](模块能力.md) 不再复述页数/菜单数 |

纪律：
1. **改内容即改「最后更新」**，日期落后于正文视为文档缺陷；
2. 发现两处数字冲突时，**先去代码/配置核实**，再改错的一方，并把结论写进本次提交信息；
3. 新增文档必须挂到本文件的索引里，并补齐「文档信息」块。
