## 1. 菜单结构

侧边栏顶层 **18 项**（13 个平铺页 + 5 个分组），按**使用频率 × 使用角色**排序，即真实项目里的运营节奏：

```
【看板】   数据概览
【上手】   功能指南
【日常运营】排队监控 · 坐席工作台 · 会话记录 · 客户管理 · 工单管理
【持续运营】▾ 知识库(10)
【定期分析】报表中心
【搭建期】 接入向导
          ▾ 开放接入(7)
          ▾ AI 能力(5)
【低频配置】坐席管理 · 工单字段 · 工单流程 · 数据保留
【平台】   ▾ 运维(7)
          ▾ 系统管理(6)
```

**为什么按使用频率排，而不是按「数据流转顺序」排**：

配置与搭建类功能（接入向导 / 开放接入 / AI 能力 / 坐席管理 / 工单字段与流程）**只在项目上线前后或偶尔改配置时用，之后可能几个月不碰**。
若按流程顺序排，它们会占据菜单腰部，把每天都要点的排队监控 / 工作台 / 会话 / 工单挤到下面——
**运营人员每天要滚动才能找到高频页**，这是最该避免的。

| 段 | 使用频率 | 排序依据 |
|----|---------|---------|
| 看板 | 每天 | 登录落地页（`/dashboard`），必须第一位 |
| 上手 | 读一次 | 新人第二眼就该看到。它不参与业务流程、熟练后自然跳过，占前排成本低；放到底部反而最需要它的人最难找到 |
| 日常运营 | 每天多次 | 前 7 位内不用滚动。段内顺序即一次服务：谁在等 → 谁在接 → 聊了什么 → 是谁 → 要跟进什么 |
| 持续运营 | 每天 | 知识库不是一次性配置：知识运营每天看未命中、补问答、调召回参数 |
| 定期分析 | 周 / 月 | 「打开看一眼」已由数据概览覆盖，报表是深挖与汇报工具，不必占前排 |
| 搭建期 | 上线前后 | 先把系统接起来 → 再配大脑 |
| 低频配置 | 偶尔 | 坐席管理是加人 / 改状态，不是坐席干活的地方（那是坐席工作台），两者分开是刻意的 |
| 平台 | IT / 超管 | 含角色不可见的项，放最底 |

> **与上两版的差异**：本版把**「报表中心」从第 2 位下调到第 9 位**（大厂参照：Zendesk 的 Reporting 排在业务页之后、网易七鱼把「数据」独立成组不占顶部），
> 并把**搭建链路整体后移到腰部、配置类下沉**。
> 前两版按「数据流转」排，会让低频功能占据黄金位，与真实运营节奏不符。

> **菜单已改为配置驱动**：定义在 `config/menus.js`，桌面侧栏与移动抽屉渲染**同一份配置**，
> 每项带 `roles` 过滤（按角色过滤后为空的分组整组隐藏）。
> 历史上两处菜单是手写的，曾导致移动端点不到运维的 4 个子页，改配置驱动后不再有这类偏差。

**为什么这么分**：

- 客服运营类页面（会话、客户、工单、坐席）是日常高频，点一下就到位，**保持平铺**；收进二级反而多点一次。
- 知识库（后端 15 个 Controller / 10 个功能域）与 AI 能力属于低频配置类，收进二级菜单，也为后续新增功能域预留挂载位——加页面只需在 `tabOptions` 与 `children` 各加一行。

## 2. 分组布局约定

5 个分组使用**同一套三段式结构**（复制成本极低）：

```
路由     /xxx  ──┬── parent: component: XxxLayout
                 └── children: { '' , 'a', 'b', ... }
Layout   XxxLayout.vue = <SectionSwitch :options="tabs" /> + <router-view />
菜单     <el-sub-menu index="/xxx"> + 若干 <el-menu-item>
```

| 分组 | Layout | 顶栏切片 | 子路由前缀 |
|------|--------|---------|-----------|
| 开放接入 | `views/OpenLayout.vue` | 7 | `/open/*` |
| 知识库 | `views/KnowledgeLayout.vue` | 10 | `/knowledge/*` |
| AI 能力 | `views/ai/AiLayout.vue` | 5 | `/ai/*` |
| 运维 | `views/ops/OpsLayout.vue` | 7 | `/ops/*` |
| 系统管理 | `views/system/SystemLayout.vue` | 6 | `/system/*` |

**页面写法约定**：分组内的页面**不要在页内重复顶栏切片已经写明的标题**，统一用

```vue
<div class="page-card">
  <p class="hint">一句话说明本页做什么</p>
  <div class="page-toolbar is-actions-only">…操作按钮…</div>
  …内容…
</div>
```

反例（已全部整改）：`<h3>用户管理</h3>` 上面已经有标签写着「用户管理」，属于重复。

**表单约定**：配置类表单的字段应**按当前选项动态显隐**，只显示真正生效的参数（例：切片策略选「分层切片」时不显示 `chunkSize`，因为后端不读它）。

**「可选可输入」约定**：枚举型字段优先做成「下拉可选 + 允许手动输入新建」，例如工具分类、图标、主题色（取色器 + hex 输入）。

### 3.7 登录与入口（两个独立页面）

前端**没有**「选择入口」中转页，两个入口各自是完整页面，互不共用表单：

| 路由 | 页面 | 左侧品牌区 | 准入 | 登录后 |
|------|------|-----------|------|--------|
| `/login` | `UserLoginPage` | 亮蓝渐变 | 普通用户（坐席账号） | `/chat` |
| `/login/admin` | `AdminLoginPage` | **深蓝黑** | 管理员 / 超级管理员 | `/dashboard` |

- `/` 与 `/login/platform` 均重定向到 `/login`（兼容旧收藏与外链）
- 两个页面底部各有一个**很轻的互跳链接**：内部人员找得到后台，C 端客户不会被吸引过去
- 运营后台页在表单上方明确标注「仅限管理员与超级管理员账号」，避免试完账号才知道进不来
- 左栏配色不只是装饰差异：让人一眼知道自己在哪个入口，减少把后台当业务页操作
- 布局是**左右分栏**：左栏放标识 / 系统名 / 一句话定位 / ✓ 能力清单，右栏放表单。
  能力清单两个入口刻意不同（C 端讲接待与转人工，后台讲集中管理与调参），进一步强化入口区分
- `LoginStage` 用 `variant`（`light` / `dark`）+ `logo` / `title` / `subtitle` / `features` / `showHelp`
  复用同一套布局，两个入口只是传入的数据不同，不再需要独立的舞台组件
- 演示账号做成可点击色块（点一下自动填账号密码），省去演示时手敲

> **安全边界**：入口分离只是体验层。真正的准入判断在服务端
> （`UserService.assertAdminEntrance`，在密码校验通过后按角色拒绝），
> 前端隐藏入口挡不住直接构造请求。详见 [接口说明 §2.1](接口说明.md)。

### 3.9 权限与角色

权限分**两层**，别混：

| 层 | 定义在 | 管什么 |
|----|--------|--------|
| **档位**（`ROLE`） | `utils/auth.js` | 入口隔离与粗粒度准入：平台账号只能进聊天、超管专属页挡住其它角色 |
| **岗位角色**（`ROLE_CODE`） | `utils/auth.js` + `config/menus.js` | 岗位职责：侧栏看到哪些菜单、能进哪些路径 |

菜单可见性与路由守卫**共用 `config/menus.js` 里的同一份角色矩阵**——`menusOfRoles()` 过滤侧栏、`canVisitPath()` 拦路径，
不会出现「菜单藏了但手敲地址能进」。一个账号可挂多个角色，**权限取并集**。

**五个岗位角色**（编码与后端 `cs_role.role_code` 对齐）：

| 角色 | 编码 | 顶层菜单 | 可见范围 |
|------|------|---------|---------|
| 一线坐席 | `AGENT` | 5 项 | 概览 · 指南 · 坐席工作台 · 会话记录 · 工单管理 |
| 客服主管 | `SUPERVISOR` | 8 项 | 坐席全部 **+** 排队监控 · 客户管理 · 报表中心 |
| 知识运营 | `KNOWLEDGE_OPS` | 4 项 | 概览 · 指南 · 知识库 · 报表中心 |
| 运营管理员 | `ADMIN` | 17 项 | 业务运营全部（搭建、配置、运维），**无系统管理** |
| 超级管理员 | `SUPER_ADMIN` | 18 项 | 全部 **+** 系统管理整组；审计可看全量并可删除 |

**档位**（`getRole()` 的返回值，用于入口隔离与超管判断）：

| 档位 | 来源 | 说明 |
|------|------|------|
| `platform` | 登录时 `loginType=platform` | C 端客户，仅聊天与帮助中心，无侧栏 |
| `admin` | 其它后台账号 | 所有非超管的后台岗位都归这一档，粗粒度准入按它判断 |
| `super` | `roles` 含 `SUPER_ADMIN`，或种子账号 `admin` | 系统管理与审计删除 |

> **落地页按岗位给**：坐席落到 `/workspace`、知识运营落到 `/knowledge`，主管与管理员落 `/dashboard`。
> 否则低权限角色的首页会被自己的权限挡一次，看着像登录失败。
>
> **演示账号**（密码任意）：`admin` 超管 / `operator` 运营管理员 / `supervisor` 客服主管 / `kops` 知识运营 / `agent` 一线坐席。
> 登录页的演示色块已按岗位列出，点一下即可切换角色看菜单差异。

**路径分组常量**（改路由时须同步）：

| 常量 | 作用 |
|------|------|
| `ADMIN_ONLY_PREFIXES` | 平台账号禁止进入的后台路径前缀。**新增分组路由必须补**，否则普通用户权限判断会错乱 |
| `PLATFORM_ONLY_PREFIXES` | 仅普通用户可用（`/chat`），管理员访问回后台首页 |
| `PLATFORM_ALLOWED_PREFIXES` | 普通用户可访问页（`/chat`、`/help-center`） |
| `SUPER_ONLY_PREFIXES` | 超管专属（`/system/user`、`role`、`menu`、`config`、`tenant`、`skill-group`），管理员访问被挡回并提示「该功能仅超级管理员可用」 |

### 3.10 管理端功能指南

| 路由 | 页面 | 说明 |
|------|------|------|
| `/guide` | `AdminGuidePage` | 管理端帮助中心。内容在 `config/guide.js`，8 个模块各讲「解决什么问题 / 关键概念 / 上手步骤 / 容易踩的坑」，顶部支持跨模块概念搜索 |

> 与 C 端 `/help-center` 是**两套内容**：那边是访客查 FAQ 的自助页，这边是给刚接手系统的人做业务扫盲。
> 侧栏「功能指南」与顶栏入口只对管理员及以上开放。

### 3.11「提示词与检索」页的标签结构

`/knowledge/settings` 现在有 5 个标签，构成「改提示词」的完整链路：

```
提示词模板 → 当前配置 → 版本与发布 → 效果评测 → 检索参数
  复用         改          存档待发布      把关        召回
```

前四个属于话术调整，检索参数独立一层（管召回，不管话术）。
「版本与发布」「效果评测」的接口契约见 [提示词版本与评测-接口约定](提示词版本与评测-接口约定.md)。

## 4. 演示模式

前端**默认走本地 mock**，不依赖后端即可浏览全部页面。

| 开关 | 位置 | 说明 |
|------|------|------|
| `VITE_USE_REAL_API` | `.env.development` | 默认 `false`；接真后端改 `true` 并**重启** `npm run dev` |
| `localStorage.aiCsUseRealApi` | 浏览器 | 运行时可覆盖，便于临时切真后端 |
| `USE_MOCK` | `ai-cs-miniprogram/utils/config.js` | 小程序侧同款开关 |

mock 数据在 `src/mock/index.js`，与后端 `Result` 结构一致（`{ code, msg, data }`）。新增页面的 mock 需同步补齐，否则页面会落到兜底提示「演示模式未覆盖该接口」。

**后端未完成接口的约定**：mock 返回演示数据（页面看起来可用），真实后端若是内存桩则页面固定显示「后端未完成」横幅；查询类占位还会带 `implemented: false`。两端行为有意区分——演示能点、联调时保持诚实。

## 5. 小程序对应页

`ai-cs-miniprogram`（微信小程序原生）**只做 C 端客服界面，不含任何运营功能**，与 Web 端不是一一对应。

小程序共 **7 个页面**：

| 小程序页 | 对应 Web 页 | 说明 |
|---------|------------|------|
| `pages/index` | — | 首页（tab） |
| `pages/chat` | `/chat` | 智能咨询（tab）。**支持对话附件**：输入栏 `＋` 弹出来源面板（选择图片 / 拍照 / 选择文件），图片点击 `previewImage` 放大，其他类型复制链接；附件随文字一起发送，也支持纯附件。⚠️ 微信**不提供剪贴板图片 API**，故无法「拷贝图片直接粘贴」（Web 端可），文本粘贴由 textarea 原生支持 |
| `pages/help` | `/help-center` | 帮助中心（tab） |
| `pages/profile` | — | 我的（tab） |
| `pages/login` | `/login` | C 端登录 |
| `pages/sessions` | `/session` | 我的会话 |
| `pages/workorder` | `/workorder` | 我的工单 |

> **运营功能一律不进小程序**：运维、系统管理、知识库配置、AI 配置、开放接入、多租户等页面
> 只在 Web 管理端提供。
> 曾有一版把 38 个运营页也搬进了小程序（`app.json` 的 `pages` 一度有 45 项），
> 与「小程序面向 C 端」的定位一致：小程序只保留 C 端 7 页，`app.json` 同步收窄。
> **新增小程序页之前，先确认它是不是 C 端能力**。

## 6. 维护约定

- **加分组**：复制任一 `XxxLayout.vue`，在路由加父记录 + `children`，再在 `config/menus.js` 加一个分组项（两侧栏共用同一份配置）。
- **加页面**：路由 + 菜单 + `api/index.js` 函数 + `mock` 处理器，四处齐了页面才不会空转。
- **加分组子页**：`XxxLayout.vue` 的 `tabOptions` 必须与 `config/menus.js` 里该分组的 `children`
  **数量与顺序一一对应**。曾经 AI 能力漏了这一条：侧栏有「坐席辅助」点得进去，顶栏却没有对应切片，
  页面看起来像走错了地方——这个偏差只能靠两边同时改来避免。
- **改路由路径**：必须同步 `utils/auth.js` 的 `ADMIN_ONLY_PREFIXES`，并给旧路径留 `redirect`。
- **加页面后回填指南**：`config/guide.js` 的模块要能覆盖新增页面，否则「功能指南」对新人不完整。
  指南里的概念会自动进顶部搜索索引（`GUIDE_SEARCH_INDEX` 由各模块 `concepts` 派生），补概念即补搜索，不用另维护一份索引。
- **加接口**：若前端调用而后端未实现，先在对应 Controller 留**空方法**并返回 `implemented: false`，同时在 mock 补齐演示数据。
- 本文只记路由与对接状态；接口字段与示例写 [接口说明](接口说明.md)。
