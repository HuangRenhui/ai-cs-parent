## 表结构详情（核心业务表）

### 1. cs_customer (客户信息表)

存储客户的基本信息和标签。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 客户ID（主键） |
| phone | VARCHAR(20) | 手机号 |
| email | VARCHAR(128) | 邮箱 |
| nickname | VARCHAR(100) | 昵称 |
| gender | TINYINT | 1-男，2-女，空-未选 |
| avatar | VARCHAR(500) | 头像URL |
| customer_tag | VARCHAR(200) | 客户标签 |
| del_flag | TINYINT | 删除标记：0-未删除，1-已删除 |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |

**索引**:
- PRIMARY KEY: `id`
- INDEX: `idx_phone`
- INDEX: `idx_del_flag`

### 2. cs_agent (坐席信息表)

存储客服坐席的账号和状态信息。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 坐席ID（主键） |
| agent_account | VARCHAR(50) | 坐席账号（唯一） |
| agent_pwd | VARCHAR(100) | 坐席密码（加密存储） |
| agent_name | VARCHAR(50) | 坐席姓名 |
| agent_status | TINYINT | 坐席状态：0-离线，1-在线，2-忙碌 |
| del_flag | TINYINT | 删除标记：0-未删除，1-已删除 |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |

**索引**:
- PRIMARY KEY: `id`
- UNIQUE KEY: `uk_agent_account`
- INDEX: `idx_agent_status`
- INDEX: `idx_del_flag`

### 3. cs_chat_session (聊天会话表)

记录每次聊天的会话信息，支持 AI 客服和人工客服。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 会话ID（主键） |
| session_id | VARCHAR(64) | 会话唯一标识 |
| customer_id | BIGINT | 客户ID（匿名访客为 0） |
| visitor_ref | VARCHAR(128) | 外部访客标识，匿名登录合并用；已有库需 `ALTER TABLE cs_chat_session ADD COLUMN visitor_ref VARCHAR(128) NULL, ADD KEY idx_visitor_ref (visitor_ref);` |
| agent_id | BIGINT | 坐席ID（可为空） |
| session_type | TINYINT | 会话类型：1-AI客服，2-人工客服 |
| session_status | TINYINT | 会话状态：1-进行中，2-已结束 |
| start_time | DATETIME | 开始时间 |
| end_time | DATETIME | 结束时间 |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |

**索引**:
- PRIMARY KEY: `id`
- UNIQUE KEY: `uk_session_id`

- INDEX: `idx_visitor_ref`
- INDEX: `idx_agent_id`
- INDEX: `idx_start_time`

### 4. cs_chat_msg (聊天消息表)

存储聊天过程中的所有消息记录。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 消息ID（主键） |
| session_id | VARCHAR(64) | 会话ID |
| msg_content | TEXT | 消息内容（**纯附件消息可为空串**） |
| msg_type | TINYINT | 发送方：1-用户，2-AI，3-坐席（`MsgTypeEnum`） |
| attachments | JSON | 消息附件列表（图片/文档等，JSON 数组；空表示纯文本消息） |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |

**attachments 结构**（JSON 数组，每项字段）：

| 字段 | 说明 |

| fileId | 附件唯一标识 |

| fileName | 原始文件名 |
| category | 大类：image / document / audio / video / archive / other |
| contentType | MIME 类型 |
| fileSize | 文件大小（字节） |

**索引**:
- PRIMARY KEY: `id`
- INDEX: `idx_session_id`
- INDEX: `idx_create_time`

### 7.1 cs_kb_chunk (文档切片表)

文档解析后的切片落库载体：切片文本**先落库再向量化**，主键 `id` 同时作为 Milvus 切片集合的主键 `chunk_id`，
检索命中后可回表取切片全文与来源文档；文档重切/删除按 `document_id` 清理。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键ID（自增，即 Milvus `chunk_id`） |
| tenant_code | VARCHAR(64) | 租户编码，默认 `default` |
| document_id | VARCHAR(64) | 来源文档ID |
| document_name | VARCHAR(256) | 来源文档名称 |
| chunk_index | INT | 文档内切片序号（从 0 开始） |
| content | TEXT | 切片文本 |
| vectorized | TINYINT | 是否已写入向量库：0-未向量化，1-已向量化 |
| del_flag | TINYINT | 删除标记：0-未删除，1-已删除 |
| create_time / update_time | DATETIME | 创建 / 更新时间 |

**索引**:
- PRIMARY KEY: `id`
- UNIQUE KEY: `uk_tenant_document_chunk` (`tenant_code`, `document_id`, `chunk_index`) —— **唯一键必须含租户**：`document_id` 常取文件名，不同租户同名文件会冲突
- INDEX: `idx_document_id` / `idx_tenant_code` / `idx_vectorized` / `idx_del_flag`

## Milvus 向量数据库

向量按**租户隔离**存放：每类向量「一租户一集合」，集合名 =
`milvus.collection-name`（或 `milvus.chunk-collection-name`）+ `_` + 归一化租户 + `_` + 短哈希；
由 `knowledge/util/MilvusUtil` 在首次写入时懒建（IVF_FLAT 索引 + COSINE 距离）并 load。

### Collection: FAQ 集合（`cs_kb_faq_{租户}_{hash}`）

存储 FAQ 的「分类 + 问 + 答」文本向量，支持语义相似度检索。

**字段**:
- `faq_id`: INT64 - 主键，关联 `cs_knowledge_faq.id`（非自增，按 faqId 幂等 upsert）
- `tenant_id`: VARCHAR(64) - 租户编码（检索时再过滤一次，防归一化碰撞串租）
- `content`: VARCHAR - 参与检索的文本（写入前按 `milvus.content-max-length` 截断）
- `embedding`: FLOAT_VECTOR - 维度取 `milvus.dimension`（默认 1024，须与向量模型输出一致）

### Collection: 文档切片集合（`cs_kb_chunk_{租户}_{hash}`）

存储文档切片向量（文档 RAG 投喂用），与 FAQ 集合分离。

**字段**:
- `chunk_id`: INT64 - 主键，关联 `cs_kb_chunk.id`（非自增，按 chunkId 幂等 upsert）
- `tenant_id`: VARCHAR(64) - 租户编码
- `document_id`: VARCHAR(64) - 来源文档ID（`cs_document_version.document_id`）
- `chunk_index`: INT32 - 文档内切片序号
- `content`: VARCHAR - 切片文本
- `embedding`: FLOAT_VECTOR - 同上

**索引与检索参数**:
- 两套集合均建 IVF_FLAT 索引，距离度量 COSINE；建索引 `nlist=milvus.nlist`，检索 `nprobe=milvus.nprobe`
- 检索结果按 `milvus.score-threshold`（默认 0.40，COSINE 越大越相似）过滤，条数取 `milvus.top-k`

> 早期设计里的单集合 `faq_vectors`（VARCHAR 主键 + 768 维）**未采用**，以本段与 `MilvusUtil` 实现为准。

## 数据库初始化

执行以下命令初始化数据库：

```bash
mysql -u root -p < docs/database/init.sql
```

脚本含业务表、开放层、RBAC 与演示种子。`DROP TABLE` 会清空已有表，不要对生产库重复执行。生产禁止使用明文种子账号（见 [功能清单](功能清单.md) §16.2）。

已有库若仍是非唯一 `idx_open_invoke_idem`，先清重复再改唯一键：

```sql
ALTER TABLE cs_open_tool_invoke DROP INDEX idx_open_invoke_idem;
ALTER TABLE cs_open_tool_invoke ADD UNIQUE KEY uk_open_invoke_idem (idempotency_key);
```

MySQL 允许多个 `NULL` 幂等键。坐席密码列现为 BCrypt 哈希，旧明文需重置。

已有库需补 `cs_ai_model` / `cs_model_usage` 表时，直接从 `docs/database/init.sql` 中复制对应的 `CREATE TABLE` 段执行即可（不要对生产重复执行 `DROP TABLE`）。

`cs_kb_chunk`（文档切片表）为 2026-09-22 新增，同样按上述方式执行其 `CREATE TABLE` 段即可。

## ⚠️ 注意事项

1. **密码安全**: 坐席与登录用户密码均为 BCrypt；生产必须设置 `JWT_SECRET`
2. **数据备份**: 定期备份数据库，建议每日全量备份
3. **索引优化**: 根据实际查询场景优化索引
4. **软删除**: 所有业务表使用 `del_flag` 实现逻辑删除
5. **时间戳**: 使用 `create_time` 和 `update_time` 自动维护记录时间

当前未接入 Flyway。表结构变更改 [init.sql](database/init.sql) 并同步本文；已有库自行 `ALTER`。禁止在内核脚本里加订单/银行卡/门店表（见 [系统架构](系统架构.md)）。
