## 5. 前后端接口对齐盘点

按「前端 `ai-cs-frontend/src/api/index.js` 的每一个调用」对「后端全部 Controller」做过一次全量比对，
结论如下（比对口径：前端 `baseURL=/api` + 路径，与后端 `@RequestMapping` 拼接后逐条对齐；
注意 knowledge 模块的 Controller 路径**自带 `/api` 前缀**，且 Vite 对 `/api/prompt`、`/api/document`
等不做 rewrite，两端的 `/api` 需按实际落点对齐）。

### 5.1 有前端页面、无后端接口 → 已补齐

盘点时共 **24 条**前端调用在后端找不到对应实现，**均已补为空实现（内存桩），当前可直接联调**：

| 模块 | 接口 | 后端位置 | 状态 |
|------|------|----------|------|
| 开放接入 | `POST /open/pack/save`、`PUT /open/pack/update`、`DELETE /open/pack/delete/{code}` | `ai-cs-open` `OpenPackController` | **后端未完成**，不持久化 |
| 开放接入 | `GET /open/widget-config/list`、`POST /save`、`PUT /update`、`PUT /{id}/enabled`、`DELETE /delete/{id}` | `ai-cs-open` `OpenWidgetConfigController` | **后端未完成**，内存多套配置 |
| 知识库 | `GET/POST /api/prompt/version/**`（6 条） | `ai-cs-knowledge` `PromptVersionController` | **后端未完成**，内存桩 |
| 知识库 | `GET/POST /api/prompt/eval/**`（10 条） | `ai-cs-knowledge` `PromptEvalController` | **后端未完成**，内存桩 |

补完后重跑比对：**前端 251 个调用全部有后端对应，A 段清零。**
版本与评测的完整表结构与实现要点见 [提示词版本与评测-接口约定](提示词版本与评测-接口约定.md)。

### 5.2 有后端接口、无前端页面

后端 477 个接口中约 **226 个未见前端调用**，主要是知识库模块的增强能力，**属于有意为之**
（后端先行铺开、前端按业务逐步页面化），不是遗漏：

| 一级路径 | 未调用数 | 主要来源 |
|----------|----------|----------|
| `api` | 174 | knowledge 增强类：`/api/image/enhance`、`/api/audio/enhance`、`/api/knowledge-enhanced`、`/api/multimodal`、`/api/video`、`/api/file` —— 去重、版本、批量、OCR、防盗链、GraphRAG、3D 模型等 |
| `ai` | 12 | agent 侧工具链与语音接口（前端只用了 `/ai/chat/send`、`/ai/chat/interrupt`） |
| `open` | 11 | 卡片模板、连接器字段映射、出站白名单等尚未页面化的部分 |
| `workorder` | 9 | 工单流程（Flowable）相关 |
| `system` | 8 | 系统侧未页面化接口 |
| `statistics` | 4 | 部分统计口径前端未用 |
| 其它 | 8 | session / knowledge / file / ops / customer |

> 如需页面化，建议按业务优先级挑，不要一次全做。**这份清单是「可选能力」，不是待修缺陷。**

### 5.3 维护约定

- 新增前端调用前，先确认后端是否已有对应接口；没有则在对应模块补一个**带 TODO 的占位方法**，
  并在 [接口说明](接口说明.md) 标注「当前为占位实现」。
- 补占位方法时注意**模块依赖差异**：`ai-cs-open` **未引入 Swagger 依赖**，不要用 `@Operation` /
  `@Parameter` 注解，接口说明沿用 Javadoc。
