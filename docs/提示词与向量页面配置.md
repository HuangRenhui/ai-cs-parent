## 4. 设计约定

**后端**

- `GET` 返回**嵌套**结构（`roleConfig.systemRole`），`POST` 收**扁平**结构（`systemRole`）——历史原因，前端需双向转换。
- 占位接口统一返回 `implemented: false` 或明确的提示文案，**不要假装成功**，前端据此展示「后端未完成」警示横幅。
- 新增配置项一律带 `tenantCode` 参数，为后续租户覆盖留位。

**前端**

- 配置类页面统一「**列表 + 表单**」结构：模板/策略/工具各自可命名保存多套。
- 表单字段按**当前选项动态显隐**，只显示真正生效的参数，避免用户调到无效项。
- 环境变量：`.env.development` 的 `VITE_USE_REAL_API`；默认 mock，接真后端须改为 `true` 并重启 `npm run dev`。

### 5.1 提示词页面化

#### 设计目标

当前提示词集中在 `PromptConst`，改完须编译重启。页面化后，运营后台可通过管理页修改提示词，无需发版。

#### 目标交互

侧栏「AI 配置」下增加 **提示词管理**（或挂在现有「AI模型管理」旁）。

- **列表**：编码、场景、行业包（空=内核默认）、启用、更新时间
- **编辑**：system / user 模板（或单段模板 + 固定话术）、变量说明、预览
- **预览**：填模拟用户问题 / 参考资料，调用现有 preview 逻辑，展示将发给模型的文本或 messages
- **操作**：启用/停用、恢复内置（把该场景写回 `PromptConst` 内容，不删行）
- **权限**：仅运营后台；C 端不出现

#### 场景编码映射

| `scene` | 对应 | 说明 |
|---------|------|------|
| `INTENT` | `PromptConst.INTENT_PROMPT` | 只输出 JSON；内核仍校验 intent 白名单 |
| `CHAT` | `CHAT_PROMPT` | 闲聊 / 非 RAG |
| `RAG` | `RAG_PROMPT` | 知识库生成 |
| `TRANSFER` | `TRANSFER_REPLY` | 固定话术 |
| `LLM_BUSY` | `LLM_BUSY_REPLY` | 固定话术 |
| `NO_KNOWLEDGE` | `NO_KNOWLEDGE_REPLY` | 固定话术 |
| `TOOL_BUSY` | `TOOL_BUSY_REPLY` | 固定话术 |
| `RAG_STRATEGY` | `PromptProperties` | 可选：把六大策略（角色/格式/CoT 等）做成可保存的一套配置 |

变量继续用 `PromptConst.fill` 的占位（按出现顺序的 `%s`），**禁止** `String.format`。

行业包：`pack_code` 可空。启用某包时，同 `scene` 优先用该包模板，否则用内核默认行。

#### 表结构设计（开工时写入 `init.sql`）

`cs_prompt_template`

| 列 | 类型 | 说明 |
|----|------|------|
| id | BIGINT PK | |
| scene | VARCHAR(32) | 上表 scene |
| pack_code | VARCHAR(64) | 空=内核默认；非空对应 `cs_open_pack.code` |
| name | VARCHAR(100) | 显示名 |
| system_text | TEXT | 可空；固定话术可只放 `user_text` |
| user_text | TEXT | 模板正文 |
| variables_json | VARCHAR(500) | 文档用，如 `["history","question"]` |
| enabled | TINYINT | 1 启用 |
| version | INT | 乐观锁 / 回滚线索 |
| remark | VARCHAR(500) | |
| create_time / update_time | DATETIME | |

唯一约束建议：`(scene, pack_code)`（`pack_code` 用空字符串代替 NULL，避免 MySQL 唯一索引对 NULL 不生效）。

不在此表存 API Key。不把整段用户对话回写此表。

#### 运行时架构

```
管理页 CRUD（建议 base-service /system/prompt）
        │ 写库 + Redis 广播（类似 cs_ai_model）
        ▼
agent / knowledge 读：启用模板 → 否则 PromptConst / PromptProperties
```

- 消费端 5 秒级懒加载即可，与 `ModelRouter` 一致。
- `INTENT` 替换后，输出仍必须是 `{"intent","entity"}`；解析失败走现有 `llmDegraded`，不按咨询路由。
- RAG 主路径若启用了库表 `RAG` 模板，与 `PromptTemplateService` 六大策略的关系：**先定一种默认**——要么「库表模板整段替换 RAG_PROMPT」，要么「库表只覆盖角色/边界，策略仍走 yml」。推荐：**主路径（INTENT/CHAT/RAG/话术）走库表；六大策略仍给文档 RAG 调试，直到 `RAG_STRATEGY` 行被显式启用。**

#### 接口草案（开工时写入 [接口说明](接口说明.md)）

前缀建议：`/system/prompt`（网关走 base-service，与 `/system/ai-model` 同权）。

现有 `/api/prompt/**` 继续给 knowledge 调试用，不要改成这张表的唯一入口。

#### 前端实现

- 路由 `/prompt`，菜单「提示词管理」
- 与 `AiModelPage.vue` 同一套鉴权
- 编辑器用普通多行文本即可，不必上代码编辑器依赖

#### 实现顺序

2. agent `LlmUtil`、knowledge `RagSearchService` 改为「库表优先」

### 5.2 向量配置页面化

#### 设计目标

当前向量库地址、集合名、维度写在 knowledge 的 `application.yml`，运维改完要重启。页面化后，运营后台可通过管理页配置向量库连接，无需发版。

#### 现状（保持到开工前）

| 项 | 现在怎么配 |
|----|------------|
| Embedding 模型 | `cs_ai_model` 且 `model_type=EMBEDDING` 生效；未登记回退 `ai.embedding` |
| FAQ 向量库 | knowledge `milvus.host/port/collection-name/top-k/score-threshold/dimension` |
| 文档 RAG 向量库 | `rag.chroma.*` + `rag.ollama.embedding-model`（旁路） |
| 前端 | 无；模型页可登记 Embedding，但看不到 Milvus/Chroma 地址 |

主路径向量化已走 `ModelRouter.embed`，**不要再写 localhost:8000 第三套客户端**，见 [配置说明](配置说明.md)。

#### 目标交互

独立页 **向量配置**（不要和对话模型混成一张无筛选的表）。页面分两块：

**A. Embedding 模型（读 `cs_ai_model`）**

- 展示当前生效 Embedding：供应方、上游模型名、维度、健康
- 「设为生效 / 测试连接」复用 `/system/ai-model`，本页不新造一套模型 CRUD
- 切换生效模型时：若 **维度与集合不一致**，弹窗阻止或要求勾选「我知道需要全量重建 FAQ 向量」

**B. 向量库连接**

| 字段 | 说明 |
|------|------|
| store_type | `MILVUS`（FAQ 主路径）/ `CHROMA`（文档 RAG 旁路） |
| host / port 或 base_url | |
| collection_name | 如 `cs_kb_faq` |
| dimension | 须与生效 Embedding 一致 |
| top_k / score_threshold | 检索参数 |
| enabled | 该条是否用于对应通路 |

操作：保存、测试连接（建连/列集合即可，不要在测连时写入向量）、只读展示集合是否已 load。

FAQ 主路径与文档 RAG 旁路必须两条配置、页面上分开标注，避免改 Chroma 却以为改了咨询检索。
