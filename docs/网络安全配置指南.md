## 安全架构概述

系统采用多层安全防护架构：

1. **网关层安全**：API 网关作为统一入口，实施认证、授权、限流、IP 访问控制
2. **传输层安全**：HTTPS 加密传输，防止中间人攻击
3. **应用层安全**：请求验证、SQL 注入防护、XSS 防护
4. **服务间安全**：内部令牌验证，防止直连绕过网关
5. **数据层安全**：数据库连接加密、敏感数据加密存储

## 网关安全配置

### 1. 安全响应头

网关自动为所有响应添加以下安全头：

- `X-Content-Type-Options: nosniff` - 防止 MIME 类型嗅探
- `X-Frame-Options: SAMEORIGIN` - 防止点击劫持
- `X-XSS-Protection: 1; mode=block` - 启用 XSS 过滤
- `Referrer-Policy: strict-origin-when-cross-origin` - 控制 Referrer 信息泄露
- `Strict-Transport-Security: max-age=31536000; includeSubDomains` - 强制 HTTPS
- `Content-Security-Policy` - 内容安全策略，防止 XSS 和数据注入
- `Permissions-Policy` - 限制浏览器功能访问

### 2. CORS 配置

CORS 配置已收紧，仅允许指定的 HTTP 方法和请求头：

```yaml
spring:
  cloud:
    gateway:
      globalcors:
        cors-configurations:
          '[/**]':
            allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:5173,http://localhost:3000}
            allowed-methods: GET,POST,PUT,DELETE,OPTIONS,PATCH
            allowed-headers: Authorization,Content-Type,Accept,X-User-Id,X-Username,X-Token-Type,X-Request-ID
            allow-credentials: true
            max-age: 3600
```

**生产环境建议**：
- 将 `CORS_ALLOWED_ORIGINS` 设置为实际的前端域名
- 避免使用通配符 `*`

### 3. IP 访问控制

新增 IP 白名单/黑名单过滤器，支持通过环境变量配置：

```yaml
security:
  ip:
    # 逗号分隔；未配置时不启用对应名单
    whitelist: 192.168.1.0/24,10.0.0.1,192.168.*.*
    blacklist: 1.2.3.4,5.6.7.8
    # 是否启用（对应 IpAccessFilter 的 security.ip.*.enabled）
    whitelist.enabled: true
    blacklist.enabled: true
```

**支持格式**：
- 精确 IP：`192.168.1.100`
- CIDR：`192.168.1.0/24`（支持 /8、/16、/24、/32）
- 通配符：`192.168.*.*`

### 4. 请求大小限制

防止 DoS 攻击，限制请求头和请求体大小：

```yaml
server:
  tomcat:
    max-http-request-header-size: 8192
    max-swallow-size: 1048576
```

### 5. 请求验证过滤器

自动检测和阻止以下攻击模式：

- **SQL 注入**：检测 `UNION SELECT`、`OR 1=1`、`--` 等模式
- **XSS 攻击**：检测 `<script>`、`javascript:`、`onerror=` 等模式
- **路径遍历**：检测 `../`、`..%2f` 等模式
- **命令注入**：检测 `|`、`&&`、`;`、`$()` 等模式

### 6. Actuator 端点安全

监控端点添加了令牌保护：

```yaml
actuator:
  security:
    token: ${ACTUATOR_TOKEN:your-secure-token}
```

访问 Actuator 端点时需要在请求头中添加：
```
X-Actuator-Token: your-secure-token
```

### 7. 限流配置

基于 Redis 的令牌桶限流，不同路由有不同的限流策略：

```yaml
# 登录接口（防撞库）
redis-rate-limiter.replenishRate: 5
redis-rate-limiter.burstCapacity: 10

# AI 接口
redis-rate-limiter.replenishRate: 20
redis-rate-limiter.burstCapacity: 40

# 基础服务
redis-rate-limiter.replenishRate: 30
redis-rate-limiter.burstCapacity: 60
```

## 服务间安全配置

### 0. 身份与授权头的信任边界（2026-09-22）

请求头 `X-User-Id` / `X-Username` / `X-Token-Type` / `X-Tenant-Id` / `X-User-Roles` / `X-User-Perms`
**只允许网关写入**，下游仅在「携带合法内部令牌」的分支采信它们：

| 场景 | 下游行为 | 防的是什么 |
|---|---|---|
| 经网关（带内部令牌） | 信任上述头，还原用户/租户/角色/权限到 `JwtContext` | 省掉每请求解析 JWT 与回查库 |
| 直连下游（无内部令牌） | **忽略这些头**，改为自行解析 JWT 的 `tenant`/`roles`/`perms` claim | 伪造 `X-User-Id` 冒充任意用户 |

配套约束（已实现）：

- 网关在注入前会**先清空客户端自带的同名头**，杜绝「客户端伪造 + 网关注入」叠加；
- `JwtSettings` 与 `InternalAuthProperties` 在 **prod profile** 下若未注入密钥/内部令牌会**拒绝启动**（不是仅告警）；
- 授权信息随 JWT 下发（`tenant`/`roles`/`perms`），因此**权限变更需重新登录或等令牌过期**；
  被 `@RequirePermission` 注解的接口，旧令牌（无授权 claim）会返回 403。

### 1. 内部令牌验证

各微服务验证请求是否来自网关，防止直连绕过网关的安全检查。

配置内部令牌：

```yaml
ai:
  internal:
    token: ${INTERNAL_API_TOKEN:your-internal-token}
```

### 2. JWT 配置

JWT 密钥必须配置，生产环境禁止使用默认值：

```yaml
ai:
  jwt:
    secret: ${JWT_SECRET:your-very-secure-jwt-secret-key-at-least-32-characters}
    expire-ms: 86400000
    visitor-expire-ms: 7200000
```

### 3. Spring Security 配置

- 使用 BCrypt 加密密码
- 无状态会话管理
- CSRF 已禁用（适用于 API 服务）
- 内部令牌验证过滤器

## 环境变量配置

生产环境必须配置以下环境变量：

```bash
# JWT 密钥（必须）
export JWT_SECRET="your-very-secure-jwt-secret-key-at-least-32-characters"

# 内部 API 令牌（必须）
export INTERNAL_API_TOKEN="your-internal-api-token"

# Actuator 监控令牌（推荐）
export ACTUATOR_TOKEN="your-actuator-token"

# CORS 允许的源（推荐）
export CORS_ALLOWED_ORIGINS="https://your-frontend-domain.com"

# IP 白名单（可选）
export SECURITY_IP_WHITELIST="192.168.1.0/24,10.0.0.1"
export SECURITY_IP_WHITELIST_ENABLED="true"

# IP 黑名单（可选）
export SECURITY_IP_BLACKLIST="1.2.3.4,5.6.7.8"
export SECURITY_IP_BLACKLIST_ENABLED="true"

# 数据库密码（必须）
export DB_PASSWORD="your-database-password"

# Redis 密码（推荐）
export REDIS_PASSWORD="your-redis-password"

# AI 模型密钥加密密钥（必须）
export AI_MODEL_SECRET="your-model-encryption-key"
```

## 安全检查清单

部署前请确认以下安全配置：

### 必须配置（高风险）

- [ ] JWT_SECRET 已设置且强度足够（至少 32 字符）
- [ ] INTERNAL_API_TOKEN 已设置
- [ ] DB_PASSWORD 已设置
- [ ] AI_MODEL_SECRET 已设置
- [ ] 生产环境禁用默认密钥

### 推荐配置（中风险）

- [ ] CORS_ALLOWED_ORIGINS 设置为实际域名
- [ ] ACTUATOR_TOKEN 已设置
- [ ] REDIS_PASSWORD 已设置
- [ ] 启用 IP 白名单（如适用）
- [ ] 启用 IP 黑名单（如适用）

### 可选配置（低风险）

- [ ] 启用 HTTPS（使用反向代理如 Nginx）

- [ ] 定期更新依赖版本
- [ ] 启用安全日志审计

## 安全最佳实践

1. **密钥管理**
   - 使用密钥管理服务（如 AWS KMS、HashiCorp Vault）
   - 定期轮换密钥
   - 不要在代码中硬编码密钥

2. **网络隔离**
   - 微服务之间使用内部网络
   - 数据库仅允许内网访问
   - Redis 仅允许内网访问

3. **监控和审计**
   - 启用安全日志记录
   - 监控异常访问模式
   - 定期审计访问日志

4. **依赖安全**
   - 定期更新依赖版本
   - 使用 OWASP Dependency Check
   - 关注安全公告

5. **数据保护**
   - 敏感数据加密存储）
   - 使用 HTTPS 传输
   - 实施数据备份策略

## 故障排查

### 1. 401 Unauthorized

- 检查 JWT_SECRET 是否配置正确
- 检查令牌是否过期
- 检查内部令牌是否匹配

### 2. 403 Forbidden

- 被 `@RequirePermission` 注解的接口（`/system/user/**`、`/system/ai-model/**`）：确认登录账号的角色在 `cs_role_menu` 里
  被授予了对应权限点（如 `system:user:list`、`ai-model:manage`），且**令牌是在授权变更之后签发的**（旧令牌需重新登录）
- 检查 IP 是否在黑名单中
- 检查 IP 是否在白名单中（如启用）
- 检查访客令牌是否越权访问

### 3. 429 Too Many Requests

- 检查限流配置是否合理
- 检查 Redis 连接是否正常
- 检查 IP 限流 Key 解析是否正确

### 4. 400 Bad Request

- 检查请求是否包含恶意模式
- 检查请求大小是否超限
- 检查请求头格式是否正确
