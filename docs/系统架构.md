## 1. 开发约束（通用内核）

智语的产品形态是 **一个通用客服平台**：任何行业把自己的业务系统接进来做客服，而不是为每个行业做一套客服。

当前仓库里的「查物流 / 退款」只是 **演示用的电商包**，不是内核能力。后续开发按本文约束，避免再把行业字段写进会话和意图枚举。

完整功能见 [功能清单](功能清单.md)。范围、接口与非功能原则见下文；落地路由见 [详细设计](详细设计.md)。

> **开发提示：** 照 [功能清单 §17](功能清单.md) 开发。通用性见 §15，上线见 §16。不要做内核「订单服务」。

---

## 一句话

内核只解决「谁在聊、怎么排、怎么答、怎么记、怎么接对方系统」。  
对方系统才解决「单、卡、店、保单、预约」是什么。

---

## 内核可以有

| 域 | 例子 |
|----|------|
| 租户与权限 | 租户、角色、坐席、审计 |
| 访客与会话 | visitor、session、message、渠道 |
| 接待 | 技能组、队列、分配、转人工 |
| 知识 | FAQ/文档，按租户隔离 |
| 工单 | 通用工单 + **自定义字段**（不要写死 orderNo） |
| 开放能力 | 连接器、工具注册、行业包开关、Webhook、卡片协议 |
| 模型网关 | 统一 Adapter；按任务路由；管理页开关（不按厂商拆服务） |
| 运维台 | `ai-cs-ops`：日志/链路/健康（不按行业拆） |
| 内核意图 | 仅保留：咨询（RAG）、投诉（建单）、转人工、调用已注册工具 |

## 内核禁止有

- 订单表、物流表、SKU、银行卡、门店、保单、预约、库存等业务主数据
- Java 枚举作为 **唯一** 意图来源（`IntentEnum` 的物流/退款应迁到「电商演示包」配置）
- 会话模型上的 `orderId` 专用字段（用 `entities[{type, id}]`）
- 提示词写死「你是电商客服」（系统提示词按租户/行业包加载）
- 按厂商拆 LLM 微服务；把 API Key 放进前端；C 端会话内换模型

行业差异全部进：**连接器配置 + 工具定义 + 知识库内容 + 提示词包**。

## 任意行业怎么接进来（不改内核代码）

行业包可随时开关：启用电商则物流/退款工具生效；关掉电商、点「仅启用金融」则只走查账类工具。这是平台能力，不是可选项。

```
1. 开租户
2. 配连接器（对方 REST/gRPC/MQ 地址与鉴权）
3. 注册工具（名称、参数 JSON Schema、映射到对方 API、权限等级）
4. 嵌 SDK：打开聊窗时带 visitorRef + scene + entities[]
5. 导入知识库；可选加载行业提示词包
6. 订阅 Webhook（可选）：会话事件回对方 CRM
```

对方系统始终是数据和动作的权威。客服只保存调用流水与会话。

### 上下文约定（SDK）

```json
{
  "tenantId": "acme",
  "channel": "web",
  "visitorRef": "user-10001",
  "scene": "product_detail",
  "entities": [
    { "type": "order", "id": "20240903001" }
  ],
  "locale": "zh-CN"
}
```

`type` 由接入方自定：`order`、`account`、`appointment`、`policy`、`ticket` 均可。内核不当枚举校验业务含义，只原样传给工具。

### 工具约定

| 字段 | 说明 |
|------|------|
| name | 如 `query_entity`、`execute_action`，或行业包预置名 |
| description | 给模型看，用于选择工具 |
| inputSchema | JSON Schema |
| risk | `read` 可自动调用；`write` / `critical` 需坐席确认或双人复核 |
| connectorId | 转发到哪条连接器 |
| timeout / idempotencyKey | 防重复退款、重复冻卡 |

电商、新零售、金融只是预置了一批 name + Schema，和客户自己导入的 OpenAPI 在内核里地位相同。

## 和当前代码的差距

| 现状 | 通用版目标 |
|------|------------|
| `IntentEnum` 写死咨询/物流/退款/投诉/转人工 | 内核三意图 + 租户工具/自定义意图 |
| `PromptConst` 已是通用客服身份；意图仍含物流/退款演示包 | 租户系统提示词 + 可选行业包 |
| `cs_open_tool` 已注册，按 `intentBind` 调用；`AiToolEnum` 未用 | LLM 按 JSON Schema Function Call |
| `/widget` 可带 `entities`；后台仍可选手动选客户聊 | 独立 SDK 包 + 匿名合并 |
| 通义收成 `DashscopeModelClient`（chat/embed）；已有 `ModelRouter` 管理页与备用链 | 意图/生成分绑、费用看板（清单 6.1） |
| JWT + RBAC 已有，单库单租户 | 租户 + 登录隔离 |

> **开发提示：** 不要新增「订单服务」来补齐电商。真实 OMS 用 REST 连接器指向对方系统。

## 目标与范围

任意行业把已有业务系统接进来即可做客服：内核负责会话、排队、机器人、坐席、工单、知识；查单、退款、冻卡、改预约等动作通过**连接器 + 工具**调用对方系统。

**范围内**：运营工作台、C 端聊窗雏形、开放层（连接器 / 工具 / 行业包）；咨询 RAG、投诉建单、转人工话术、演示用物流/退款工具；运维台（清单 §16.5）。

**范围外**：热线 IVR、企微做深、质检排班（合同默认不包含，见清单 §17-D）。内核禁止项见上一节。

逻辑分层（目标）：

```
渠道     站点 Widget/SDK · 企微 · 热线 · 对方 IM
内核     租户权限 · 会话排队 · 机器人(RAG+工具) · 坐席 · 工单 · 知识 · 模型网关
开放     连接器 · 工具注册 · 行业包 · Webhook · 卡片 · 身份映射
对方系统 OMS / POS / 核心账务 / 任意 REST
```

当前：渠道仅后台 `/chat` + `/widget`；内核 JWT 登录已有、无排队；开放层已有连接器与工具脚手架；Webhook / 卡片 / 模型网关未做。

## 接口与数据原则

- 对外只走网关 `http://localhost:8080`；前端开发用 Vite `/api` 前缀（会被剥掉）。
- 统一响应 `{ code, msg, data }`，`code=200` 成功。路径以 [接口说明](接口说明.md) 为准。
- 库名 **`ai_customer_service`**。内核表：客户、坐席、会话、消息、FAQ、工单。开放表：行业包、连接器、工具、调用审计、访客映射。
- **不建**订单 / 物流 / 银行卡表。业务实体用 `entities[{type,id}]` 透传。表结构见 [数据库设计](数据库设计.md)。

## 非功能（现状 vs 目标）

| 项 | 现状 | 目标（清单 §16） |
|----|------|------------------|
| 身份 | JWT + BCrypt + RBAC | SSO / 锁定 / 技能组数据权限 |
| 日志 | 仅 ops 模块 JSON + requestId | 全服务 MDC + 采集 |
| 追踪 | 日志聚合伪 span | OTel + Zipkin/SkyWalking |
| 健康 | ops HTTP 端口探测 | Actuator health/ready（不暴露公网） |
| 扩展 | WS 连接在进程内存 | 无状态 + 外部会话存储 |
| 安全 | Fastjson 1.2.83；连接器可打内网 | 迁出 Fastjson；SSRF 白名单 |

## 2.4 🔄 数据流向

完整时序见 [业务流程](业务流程.md)。

### 核心业务流程

1. **用户聊天流程**
   ```
   用户 → 前端 → WebSocket → AI代理 → LLM → 知识库检索 → 返回答案
   ```

2. **工单创建流程**
   ```
   用户/坐席 → 前端 → 网关 → 工单服务 → 数据库 → 通知坐席
   ```

3. **知识检索流程**
   ```
   问题 → Embedding → 向量 → Chroma/Milvus检索 → Rerank重排 → 相似FAQ → LLM生成答案 → 返回
   ```

## 2.5 🌐 部署架构

现状默认是**单机直连**：无 Nacos（`enabled: false`），网关把流量转到 `localhost:8081–8087`。`ai-cs-job` 不经网关。WebSocket 连接在进程内存，**不能**直接按下面「生产多实例」扩 `ai-cs-websocket` 副本（须先 Redis/总线，见 [功能清单 §16.2](功能清单.md)）。

容器手册见 [Docker部署](Docker部署.md)（示例 compose **未**含 open/ops/job；K8s 为可选，不挡单机可售闭环）。

## 2.6 🛡️ 安全设计

1. **网关鉴权**: JWT 过滤器 + 收紧白名单；访客令牌 `typ=visitor` 仅聊天/会话写入。WebSocket 握手须 `?token=`
2. **密码加密**: 登录用户与坐席密码均 BCrypt
3. **RBAC**: 角色菜单已有；SSO / 锁定 / MFA 仍缺
4. **HTTPS**: 生产须 TLS；当前网关 CORS 过宽
5. **SQL 注入防护**: MyBatis Plus 参数化查询
6. **XSS 防护**: 前端输入过滤和转义
7. **密钥**: `JWT_SECRET` / `ai.jwt.secret`、`AI_LLM_API_KEY` 用环境变量；未配置 JWT 时用内置默认值并打警告
8. **API 签名**: 开放层出站/入站签名**缺失**（见功能清单 §18.9）
9. **连接器 SSRF**: REST 禁内网/元数据，出站白名单仍半成品
10. **开放工具幂等**: `cs_open_tool_invoke.idempotency_key` 唯一索引；并发同一 key 不会双写

## 2.7 ⚡ 性能优化

1. **Redis 缓存**: Job 已预热 FAQ/配置/工单统计；热点策略仍可按压测再收紧
2. **数据库索引**: 表设计见 [数据库设计](数据库设计.md)；客户/工单/会话列表仍有全量查询缺口
3. **连接池**: HikariCP 已在 yml 配置，生产按并发调 `maximum-pool-size`
4. **JVM**: 启动参数示例见 [手动部署](手动部署.md)，勿照抄开发机 `-Xmx`
5. **异步 / 队列**: 耗时可先 Spring 异步与 `@Scheduled`；RabbitMQ/Kafka **未接**，且不是内核订单总线
6. **分页查询**: FAQ 已分页；其余列表见功能清单 §16.2
7. **向量检索**: Milvus 索引加速相似度搜索

## 2.8 📊 监控与日志

1. **Spring Boot Actuator**: 健康检查；gateway / base 已暴露 Prometheus
2. **日志**: 各服务 JSON 行日志 + `requestId`；`ai-cs-ops` 读本地 `logs/`（单机）
3. **链路追踪**: **未接**。落地用 Micrometer Tracing + OpenTelemetry，导出 Zipkin **或** SkyWalking（不要用已停更的 Spring Cloud Sleuth）
4. **Grafana / ELK / 告警通道**: 缺失；ops 告警页 ≠ 生产告警
5. 细节见功能清单 §16.4、§18.2、§18.3、§18.12

---

## 2.9 🔮 扩展性

1. **微服务**: 各服务独立进程；网关现为直连 URI
2. **无状态**: HTTP 服务可水平扩展；**WebSocket 除外**，连接在进程内
3. **消息队列**: 可选 RabbitMQ/Kafka；行业系统仍走开放层连接器，不在内核加 OMS
4. **Nacos**: 配置与发现已写在 yml，默认关闭；多实例 / K8s 再开
5. **高可用**: 多副本、LB、故障转移、库备份见功能清单 §18.11，当前未交付
